# Лабораторная работа №4. Ансамбли

Задание: [AKlimovUrfu/lab4](https://github.com/AKlimovUrfu/lab4).

Цель — решить задачу классификации из третьей работы с помощью ансамбля.
Я сравниваю шесть конфигураций, выбираю одну по кросс-валидации на train
и после этого измеряю качество на отложенном test.

## Данные и подготовка

Использую исходный файл `german.csv` с разделителем `;`. В нём 1000 строк
и 20 признаков. Цель — первый столбец `Creditability`.
Метка 1 встречается 700 раз, метка 0 — 300 раз.
Пропусков: 0. Полных дубликатов: 0.

Сохраняю разбиение из третьей лабораторной: `test_size=0.2`,
`random_state=42`, `stratify=y`. Получаю 800 строк в train
и 200 строк в test. В train — 560 объектов класса 1
и 240 класса 0; в test — 140 и 60 соответственно.

Семь количественных или порядковых столбцов оставляю числовыми:
`Duration_of_Credit_monthly`, `Credit_Amount`, `Instalment_per_cent`,
`Duration_in_Current_address`, `Age_years`, `No_of_Credits_at_this_Bank`,
`No_of_dependents`.

Остальные 13 столбцов считаю категориальными: `Account_Balance`,
`Payment_Status_of_Previous_Credit`, `Purpose`, `Value_Savings_Stocks`,
`Length_of_current_employment`, `Sex_Marital_Status`, `Guarantors`,
`Most_valuable_available_asset`, `Concurrent_Credits`, `Type_of_apartment`,
`Occupation`, `Telephone`, `Foreign_Worker`.
Преобразую их через `OneHotEncoder(handle_unknown='ignore', sparse_output=False)`.
Все категории сохраняю: деревьям не требуется убирать один dummy-столбец.
После подготовки число признаков равно 61.

Для возможных новых пропусков предусмотрен `SimpleImputer`: медиана для чисел,
самая частая категория для категорий. В исходной таблице он ничего не заполняет.
Деревьям масштабирование не требуется. В базовой логистической модели
дополнительно использую `StandardScaler` для числовых столбцов.

Предобработка входит в `Pipeline`. При CV она обучается заново внутри каждой
обучающей части. При итоговом обучении она видит только train. Значения
`test_target` нужны лишь для итоговых метрик.

## Гипотезы и эксперименты

Проверяю три предположения:

1. Ограничение глубины и увеличение размера листа уменьшат переобучение леса.
2. Дополнительная случайность Extra Trees может улучшить обобщение.
3. Последовательное исправление ошибок в Gradient Boosting может быть полезнее независимых деревьев.

Использую небольшой фиксированный набор из шести конфигураций.
Все параметры ниже задаются до итоговой оценки на test.

| Эксперимент | Настройки |
|---|---|
| `rf_default` | Random Forest: 250 деревьев, глубина не ограничена, min_samples_leaf=1, max_features=sqrt |
| `rf_regularized` | Random Forest: 250 деревьев, max_depth=8, min_samples_leaf=3, max_features=sqrt |
| `extra_trees` | Extra Trees: 250 деревьев, глубина не ограничена, min_samples_leaf=2, max_features=0.8 |
| `gb_shallow` | Gradient Boosting: 150 деревьев, learning_rate=0.05, max_depth=2, min_samples_leaf=5 |
| `gb_deeper` | Gradient Boosting: 150 деревьев, learning_rate=0.05, max_depth=3, min_samples_leaf=5 |
| `gb_longer` | Gradient Boosting: 300 деревьев, learning_rate=0.05, max_depth=2, min_samples_leaf=5 |

Для всех моделей `random_state=42`. У лесов `n_jobs=1`.
Остальные параметры остаются стандартными для записанной версии scikit-learn.

В Random Forest каждое дерево обучается на bootstrap-выборке train.
При поиске разбиения дерево рассматривает случайное подмножество признаков.
Итоговая вероятность — средняя вероятность класса 1 по деревьям.
Это снижает зависимость от одного дерева. Глубина 8 и минимум три объекта
в листе ограничивают сложность каждого дерева.

Extra Trees добавляет случайность при выборе порогов разбиения.
В этой конфигурации `bootstrap=False`, поэтому каждое дерево получает весь train.
Gradient Boosting строит деревья последовательно: следующее дерево помогает
уменьшить текущую ошибку log loss. Параметр `learning_rate` задаёт вклад нового дерева.

Проверяю конфигурации через `StratifiedKFold(n_splits=5, shuffle=True, random_state=42)`
только на 800 строках train. В каждом проходе 640 строк идут на обучение,
160 — на валидацию. Все модели используют одинаковые фолды.

## Метрики

Критерий выбора — максимальный средний **ROC-AUC на пяти валидационных фолдах**.
Остальные метрики показываю для понимания поведения при пороге 0.5.
ROC-AUC считаю по вероятностям. Положительный класс — исходная метка 1.
`Precision`, `Recall` и `F1` относятся к ней.

Таблица выбора модели. Все значения здесь получены на CV внутри train:

| rf_regularized | 0.778906 | 0.742500 | 0.750413 | 0.948214 | 0.837410 | 0.038890 |
| extra_trees | 0.742429 | 0.743750 | 0.793263 | 0.857143 | 0.822753 | 0.037781 |
| gb_shallow | 0.763839 | 0.750000 | 0.772508 | 0.912500 | 0.836182 | 0.030236 |

| gb_longer | 0.774144 | 0.770000 | 0.796143 | 0.903571 | 0.845864 | 0.019074 |

## Выбранная модель

Выбираю `rf_regularized`: Random Forest с 250 деревьями, глубиной 8
и минимум тремя объектами в листе. Средний CV ROC-AUC — 0.778906.
Это максимум среди проверенных конфигураций. Выбор не зависит от итогового test.

Контрактная функция `run_ensemble_experiment(data: EnsembleInput) -> EnsembleResult`
обучает эту конфигурацию и предобработку по переданному train.
Она возвращает имя модели, вероятности класса 1, метки при пороге 0.5
и все пять требуемых метрик на переданном test.
Имена и файлы `grader_contracts` сохранены.

На итоговом test ROC-AUC равен **0.836310**.
Для этого запуска он выше границы 0.80 из задания.
Это результат конкретного разбиения, а не гарантия качества на любых новых данных.

## Выводы и ограничения

Ограниченный лес улучшил средний CV ROC-AUC с 0.773084
до 0.778906, разница 0.005822.
Первая гипотеза получила поддержку по критерию выбора, но одновременно
менялись два параметра: глубина и размер листа. Их отдельный вклад я не измерял.
Рост ROC-AUC также не означает улучшения всех метрик: сравнение Accuracy и F1
при пороге 0.5 видно в таблице.

Extra Trees уступил обоим лесам. Дополнительная случайность в выбранной
конфигурации не помогла. У бустинга увеличение глубины с двух до трёх
подняло средний CV ROC-AUC с 0.763839 до 0.776339.
Увеличение числа неглубоких деревьев до 300 дало 0.774144.
Оба изменения помогли относительно `gb_shallow`, но выбранный лес остался выше.

У выбранного леса ROC-AUC на полном train — 0.953862,
Accuracy на train — 0.866250.
Сравнение с CV показывает, что риск переобучения сохраняется.
На отложенном test измеренный AUC оказался выше среднего CV.
Это может быть связано со случайностью разбиения; разница не доказывает устойчивость результата.

Данные несбалансированы в отношении 70/30. Порог 0.5 даёт много ложных
отнесений к классу 1. Для применения модели потребовалось бы определить
стоимость ошибок и подобрать порог по отдельной валидации или out-of-fold
прогнозам train. На test порог я не подбирал.

На test лес выше базовой логистической модели по ROC-AUC, но ниже по Accuracy
и немного ниже по F1. Значит, преимущество зависит от выбранного критерия.
Высокий ROC-AUC не гарантирует лучший результат при фиксированном пороге 0.5.

В таблице всего 1000 записей. Один test из 200 объектов и пять CV-фолдов
не дают окончательного вывода о превосходстве алгоритма. Я проверил небольшой
набор параметров и не исследовал нейронную сеть: задание разрешает выбрать ансамбль.
Внешних признаков и синтетических строк не добавлял.

Установка — отдельная команда пользователя. Код решения не устанавливает пакеты.

с сохранёнными значениями CV. Она проверяет совпадение данных, конфигураций,
кода предобработки и версии scikit-learn. После правок сначала нужен полный запуск.
При смене версии библиотеки возможны небольшие различия результата.

В ячейках уже сохранён фактический вывод выполненного запуска.

`experiment_results.json` содержит итоговые метрики, все CV-эксперименты,
матрицы ошибок, параметры, версии и сведения о данных.
`cv_results.json` хранит отдельные значения AUC по фолдам.
